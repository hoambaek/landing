### 2.3 뉘앙스 — 검토 후 결정할 것

- **기록의 주어.** 현재 히어로: "한 병의 샴페인이 … **시간을 기록하고** 있습니다"(병이 주어). 북극성 A안: "샴페인이 바다 아래에 **있습니다**"(사실) + "**우리는** 그 시간의 전부를 기록합니다"(헌신 선언). 병=기록매체(§4-①)로 읽으면 현재도 허용되나, §7-3 "측정은 헌신의 형식"(지켜보는 우리)의 화법은 A안 구조가 더 정확하다. 부제를 신설(N1)하면서 주어 정리를 함께 검토.
- **모토의 히어로 서명.** 북극성은 모토 확정(§3)만 하고 배치는 지시하지 않는다. 현재 푸터에만 있는 것은 위반이 아님. 다만 Krug iD·"Vintage only"식 반복 노출 문법(§비교 3.3)을 따른다면 히어로 우하단 이탤릭 서명 추가가 저비용 고효율 — **권장(선택)**.
- **v1에서 강등된 항목 2개** (근거가 북극성이 아니라 실행 레이어 문서였음): ① 인양 시계(UAPS 예측일) — 북극성엔 없고, §7-2 대시보드 경계와 긴장. 미래의 닻은 A안 부제처럼 **시점 한 줄**("다음 인양 ○○○○년 ○월")이면 충분. ② Édition Zéro 서막 명명 — 북극성 범위 밖. 채택 여부는 별도 결정.
- **§7-4 측정값에 자연의 이름** (물때 어휘 — "조금", "사리") — 검토 조항. 미적용 상태이며 급하지 않음. 큐베 서사·제품 상세에서 실험 권장.

## 3. Krug · Dom Pérignon 대비 (요지 유지)

> 북극성 §부록이 이미 두 브랜드를 참조 축으로 지정(Krug=병별 ID, DP=시간의 제품화). 에이전트가 실사이트 DOM까지 분석.

| 축 | Krug | Dom Pérignon | 뮤즈드마레 (현재) |
|---|---|---|---|
| 히어로 | 정적 이미지 + "Scroll to discover", 무헤드라인 | 풀스크린 무음 루프 영상 + "discover" | 정적 실사 + 손글씨 헤드라인 |
| 타이포 | 세리프 90px vs 산세리프 14px 극대비 | 단일 산세리프, 평평 — 영상이 위계 | Cormorant 대형 + **손글씨 한글**(고유) |
| 톤 | 크림 페이퍼 라이트 | 뉴트럴 그레이 라이트 | **다크 기반 + 라이트 교차** |
| 시그니처 장치 | **Krug iD × 3곳 상설**(헤더·메뉴·푸터앱) | **"Vintage only" × 3중**(게이트·타이틀·Manifesto) | 기록·NFC — 섹션 내부에만 |
| 커머스·CTA | 없음 — Discover/Join us | 리테일러 위임 — discover/Find nearby | 없음 — 발견·초대·문의 ✓ |

**우리가 잘 서 있는 지점:**
1. **문법이 동급** — 판매어 배제·절제된 모션(둘 다 패럴랙스·스크롤잭 없음)·에디토리얼 여백·시그니처 실사.
2. **손글씨 한글 = 두 하우스에 없는 고유 자산.** "바다가 쓴 시간"과 서체가 물리적으로 일치.
3. **다크 테마 = 근거 있는 역주행.** 현행 양대 하우스는 둘 다 라이트. 우리의 다크→라이트 교차는 서사(바다 아래→수면 위)가 뒷받침. (Krug 배경 `rgb(241,239,235)` = 우리 `--color-void-text #F1EFEB`와 동일값.)

**배울 것 2가지:**
- **B1 — 시그니처 장치의 상설 반복.** Krug iD와 "Vintage only"는 3곳 이상 반복. 우리의 "기록" 장치(카운터·기록 카드·NFC)는 각 섹션 안에 갇혀 있음. §1-6(코드 체계=Krug ID)의 우리 버전인 **NFC 기록 카드**를 섹션 밖(메뉴·게이트·헤더 중 1곳+)으로 꺼내는 것이 다음 단계. → 제품 상세 플랜([product-detail-page-plan](../plans/2026-07-02-product-detail-page-plan.md))이 본체.
- **B2 — 영상.** DP는 감정 전달을 무음 루프 영상에 전담시킴. 북극성 §10-1 "첫 인양 에셋"이 확보되면 히어로 무음 루프 전환이 "사건이 먼저, 마케팅이 나중"(§5)과 정확히 맞물림.

## 3.5 시각 감사 — 구성 · 이미지 · 디자인 (데스크톱 1440 + 모바일 390 전수 확인)

### 시각적 강점 (유지·강화)

1. **인양 케이지 = 시각적 주인공의 일관성.** 히어로(황금빛 수면 위) → Living Data(청록 심해 아래) → First Record(노을 인양 순간) — **같은 케이지가 3연속 등장**해 페이지 전반부가 사실상 한 편의 스토리보드로 읽힌다. §5(Speedmaster — 사건의 물증)의 시각 번역으로 이보다 정확할 수 없음.
2. **컬러 그레이드 통일.** 전 이미지가 웜 앰버 그레이드(노을·러스트·골드)로 정렬, **Living Data만 유일하게 쿨 청록** — "심해로의 하강"이 색온도로 표현됨. 의도가 읽히는 유일한 예외라 통일감을 깨지 않음.
3. **First Record의 전환 설계 = 페이지 최고의 순간.** 다크→라이트로 길게 풀리는 그라데이션 배경 위에 인양 사진(인셋) → 세로 hairline → 따개비 매크로가 이어지며 **"수면 위로 떠오름"을 스크롤 자체로 체험**시킴. 라이트 Collection 진입의 서사적 근거가 됨.
4. **Collection 진열 문법.** 박스 없는 컷아웃 병(contain, 물성 그대로) + 넘버링 + 한 줄 정의 = Krug의 "아카이브 열람" 문법. **아웃라인 일러스트(3년, 잠김)와 실물 사진(인양)의 대비**가 이미 "두 개의 상태"의 시각 언어를 만들고 있음 — 제품 상세 플랜과 정확히 연결.
5. **메뉴 오버레이 완성도.** 라이트 반전(#C4BFBB) + Cormorant 대형 리스트 + 심볼 워터마크 + **하단 관측 데이터 라인("기록 · 남해 34.1434°N · 수온 13.5°C · 측정 N일째")** — 시그니처 장치 상설화(P2-3)가 이미 부분 구현되어 있음.
6. **모바일 대응 정확.** 히어로 전용 크롭(h3_m2)·중앙 정렬 4행·top blur, Collection 2열 그리드, 기록 카드 축소 — 별도 크롭 에셋을 쓰는 성실한 대응.
7. **가이드 준수.** 직각 모서리·hairline·평면(글라스/섀도우 없음)·필름 그레인 — Paper 가이드 DO/DON'T 위반 미검출. Ocean(좌)·Partnership(우) 텍스트 지그재그 배치로 후반부 단조로움 회피.

### V1·V2 수정 방향

- **V1 (즉시):** `menu.recDays` 하드코딩 제거 → Living Data의 `computeDays()`(기준 `MEASURE_START = 2024-05-01`)를 공용 유틸로 추출해 메뉴 오버레이도 동일 계산 사용. 로케일 3종 모두. *(향후 P1-3 인양 기록 라인도 같은 유틸 참조 — 숫자의 단일 출처 원칙.)*
- **V2:** 스크롤 진입 후(히어로 이탈 시) 헤더에 배경 스크림 또는 워드마크 페이드 처리. 히어로 상단은 현행 유지(이미지 위 로고는 문제없음) — 충돌은 텍스트/밝은 사진 구간에서만 발생.

## 4. 개선안 (구체적 실행)

> ⚠️ **공통 제약:** 한글 히어로 타이틀(`/text/hero-h1-d.png` 563×182, `-m.png` 255×150)과 Living 도입 카피(`/text/living-copy.png`)는 손글씨 서체(J1950) **PNG 에셋**. 이들의 문구 변경은 JSON 수정이 아니라 **PNG 재제작(디자인 트랙)**. 아래 P1 항목은 전부 PNG를 건드리지 않는 **텍스트 노드 추가**로 설계했다.

### P1 — 북극성 직접 근거 · 텍스트 노드만으로 당일 가능

#### P1-1. Living Data 제품 선언 한 줄 (N2)

- **카피(§8 원문 그대로):** "이 기록은, 병과 함께 건네집니다."
- **작업:** `src/i18n/messages/{ko,en,fr}.json`에 `living.declaration` 키 신설 → `TheLivingRecordSection.tsx` 로그 라인 아래 텍스트 노드(Noto Sans KR 300, 캡션급). 대시보드화 금지 — 딱 한 줄.
- **효과:** 랜딩에서 처음으로 데이터=제품이 연결됨. 북극성이 "처음 선언하는 지점"으로 못 박은 문장.

#### P1-2. 히어로 부제(각주) 신설 (N1)

- **카피(§8 A안 부제 구조 × 1년 기준):**
  > *그 모든 날이 기록되고 있습니다. — 남해 수심 30m · 바다에서의 1년*
- **작업:** `hero.subline` 키 신설 → `HeroSection.tsx` 헤드라인 아래 `s-void__subline` 텍스트 노드(수심·기간은 IBM Plex Mono). 한글 PNG 재제작 불필요.
- **함께 검토:** 기록의 주어(§2.3) — 부제가 "기록" 선언을 받으므로 헤드라인 PNG는 차기 재제작 시 "…바다 아래에 있습니다"(A안 사실 진술)로 정리하는 안.
- **효과:** 1년 앵커(닷사이식 숫자 닻, §1-3) + 수심 30m + 기록 선언이 첫 화면에 갖춰짐.

#### P1-3. First Record에 인양 기록 라인 (N4)

- **카피(예시 — 실측값으로 교체):**

- **작업:** `first.log` 키 신설 → `TheFirstRecordSection.tsx` 헤드라인 아래 또는 사진 캡션 위치에 Mono 한 줄. Living Data 로그와 동일 포맷(§7 일관성).
- **효과:** "기록하는 브랜드"가 자기 사건(첫 인양)을 기록으로 보도 — §4-③의 "날짜·좌표·당일 해황" 요건 충족. **한 줄로 섹션의 성격이 '무드 사진'에서 '사료(史料)'로 바뀐다.**
